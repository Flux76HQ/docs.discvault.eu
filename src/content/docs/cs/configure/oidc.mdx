## Postup

1. **Vytvořte:** důvěrný klient OIDC u poskytovatele identity s přesnou adresou zpětného volání DiscVault · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **Nastavte:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · nastavte vydavatele, ID klienta a tajemství klienta společně, nebo ponechte všechny tři hodnoty prázdné; neúplná konfigurace zabrání spuštění
3. **Nastavte:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **Vyberte:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · povolte přesné privátní HTTP originy pouze pro tokenové a JWKS endpointy; issuer a autorizace v prohlížeči zůstávají jen přes HTTPS, ověření TLS zůstává zapnuté a přesměrování discovery, tokenů a JWKS jsou odmítnuta
5. **Spusťte:** `next-api` · `--force-recreate`
6. **Otestujte:** OIDC přidává volitelné přihlášení v prohlížeči; místní passkeys, volitelná hesla, obnovovací kódy, API tokeny a MCP bearer tokeny si zachovávají své role · identita je přesná dvojice issuer a subject; e-mail se nikdy nepřipojí automaticky, propojení vyžaduje přihlášenou relaci prohlížeče a odpojení vyžaduje jinou použitelnou metodu přihlášení
7. **Zkontrolujte:** `auth.oidc_failed` · selhání zaznamenají pouze nastavený zobrazovaný název poskytovatele, bezpečný kód `auth.oidc_failed` a režim toku; tajemství, tokeny, autorizační kódy, state, nonce, URL endpointů a hodnoty PKCE se nikdy nelogují

### Příkazy a nastavení

#### DiscVault v26 – beta

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```text

```
