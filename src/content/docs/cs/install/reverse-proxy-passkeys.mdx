Legacy Authentication s uživatelským jménem, heslem a dvoufaktorovým ověřením (2FA) je v DiscVault 26 beta k dispozici jako záloha, když nelze použít passkeys.

:::

## Postup

1. **Vyberte:** FQDN · mimo výjimku pro nastavení na localhost vyžadují passkeys stabilní plně kvalifikovaný název domény přes důvěryhodné HTTPS; holá IP adresa ani prosté HTTP nejsou podporovány
2. **Vyberte:** [Instalace: Legacy Authentication](/cs/install/legacy-authentication/) · pro přímou privátní nebo loopback IP bez FQDN ponechte `RP_ID` a `RP_ORIGINS` prázdné
3. **Nastavte:** `RP_ID`
4. **Nastavte:** `RP_ORIGINS` · HTTPS
5. **Nastavte:** [Konfigurace: Přihlášení přes OpenID Connect (OIDC)](/cs/configure/oidc/) · `/api/next/auth/oidc/callback`
6. **Nastavte:** `6080` `6180`
7. **Otestujte:** `GET /api/next/health`
8. **Zaznamenejte:** zvolte název hostitele před registrací passkeys; pozdější změna vyžaduje novou registraci a localhost zůstává pouze výjimkou pro místní nastavení

### Příkazy a nastavení

#### DiscVault v26 – stabilní

```text
RP_ID=discvault.example.com
RP_NAME=DiscVault
RP_ORIGINS=https://discvault.example.com
curl --fail https://discvault.example.com/api/next/health
```

#### DiscVault v26 – beta

```text
RP_ID=discvault.example.com
RP_NAME=DiscVault
RP_ORIGINS=https://discvault.example.com
LEGACY_AUTH_ENABLED=true
curl --fail http://localhost:6180/api/next/health
```

:::caution
Bezpečná hranice obnovy pro **Instalace: Reverzní proxy a přístupové klíče** vyžaduje před spuštěním nebo pokračováním tyto kroky: zvolte název hostitele před registrací passkeys; pozdější změna vyžaduje novou registraci a localhost zůstává pouze výjimkou pro místní nastavení; pouze přímý privátní nebo loopback požadavek s neplatným či prázdným RP pro passkeys může nabídnout bootstrap bez TOTP; pro uživatelské jméno, heslo a 2FA ponechte TOTP zapnuté; obnovte proxy a hodnoty RP společně a zachovejte metodu obnovení vlastníka.
