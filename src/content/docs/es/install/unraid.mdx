## Objetivo y resultado

Instala DiscVault desde la tienda Community Applications de Unraid. La plantilla instala el lanzador de DiscVault, que crea y actualiza por ti PostgreSQL, la API, el worker y MCP.

Completa el flujo específico de la página para **Instalación: Unraid**. Este procedimiento utiliza `ghcr.io/helmerznl/discvault-launcher:latest` · `/var/run/docker.sock` · `/api/next/health`.

## Aplicable a

Helmer’s Repository ofrece DiscVault y DiscVault (beta) como dos plantillas, cada una con sus carpetas appdata, puerto, proyecto Compose y red, para que funcionen en paralelo.

Esta página se aplica solo a **Instalación: Unraid** (Unraid). Sus límites de canal y datos son: DiscVault · `ghcr.io/helmerznl/discvault-launcher:latest`; `6080` · `/mnt/user/appdata/discvault` · `discvault_stack`; DiscVault · `ghcr.io/helmerznl/discvault-launcher:beta`; `6081` · `/mnt/user/appdata/discvault-beta` · `discvault_beta_stack`. Puntos de control de esta página: `ghcr.io/helmerznl/discvault-launcher:latest` · `/var/run/docker.sock` · `/api/next/health`.

## Requisitos previos

- Unraid `6.12+`
- complemento Community Applications instalado
- las passkeys necesitan una dirección HTTPS con nombre de dominio delante del puerto de la app; sin ella, usa el inicio de sesión con contraseña y TOTP

## Procedimiento

1. **Abre:** Apps → busca DiscVault → Instalar; la plantilla beta lleva (beta) en el nombre
2. **Configura:** conserva las carpetas appdata predeterminadas; la carpeta del lanzador guarda el archivo Compose generado y los secretos en `/config/stack.env` · `TZ`
3. **Configura:** `RP_ID` · `RP_ORIGINS` · las passkeys necesitan una dirección HTTPS con nombre de dominio delante del puerto de la app; sin ella, usa el inicio de sesión con contraseña y TOTP · `LEGACY_AUTH_ENABLED=true`
4. **Inicia:** el primer arranque tarda unos minutos mientras el lanzador descarga las imágenes y crea la base de datos · el lanzador monta el socket de Docker y por tanto controla Docker en el servidor; instálalo solo si confías en la imagen del lanzador
5. **Verifica:** `/api/next/health` · la configuración inicial crea el primer propietario con una passkey, o con contraseña y TOTP, y muestra una vez los códigos de recuperación
6. **Configura:** pestaña Docker → Buscar actualizaciones; al arrancar, el lanzador también actualiza el resto de la pila · `DISCVAULT_CHANNEL=manual` · `DISCVAULT_IMAGE`

El lanzador ha descargado las imágenes y creado la pila, la interfaz web responde en el puerto de la plantilla y la dirección de estado indica una base de datos migrada.

Acepta el resultado de **Instalación: Unraid** solo cuando se cumplan todos estos resultados: la configuración inicial crea el primer propietario con una passkey, o con contraseña y TOTP, y muestra una vez los códigos de recuperación; `/api/next/health` · HTTP `200` · `"status": "ok"`. ## Seguridad y reversión

:::caution
Detén la app antes de copiar sus tres carpetas appdata. Para revertir, pon el canal en manual con la etiqueta de la versión anterior y restaura la copia hecha antes de la actualización.

El límite de recuperación segura de **Instalación: Unraid** exige estas acciones antes de iniciar o continuar: la beta puede cambiar la base de datos de forma que la app estable no pueda leerla; nunca la apuntes a las carpetas de la estable; el lanzador monta el socket de Docker y por tanto controla Docker en el servidor; instálalo solo si confías en la imagen del lanzador; la copia de seguridad de la app (Administración → Backup, también programada) traslada una biblioteca entre Docker, Unraid y Home Assistant; el lanzador todavía no transmite las variables de OpenID Connect, así que la plantilla de Unraid inicia sesión con passkeys o contraseña.
