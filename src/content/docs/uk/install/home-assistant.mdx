## Мета й результат

Запускайте DiscVault як застосунок Home Assistant. Застосунок, його worker, кінцева точка MCP і PostgreSQL 17 працюють в одному контейнері, а все збережене лежить у теці даних, яку Home Assistant включає в резервні копії.

Виконайте спеціальну процедуру сторінки для **Встановлення: Home Assistant**. У цій процедурі використовуються `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

## Застосовується до

Репозиторій пропонує DiscVault на порту 6180 і DiscVault (beta) на порту 6181, кожен із власною текою даних, тож вони працюють паралельно на amd64 і aarch64.

Ця сторінка стосується лише **Встановлення: Home Assistant** (Home Assistant). Межі каналу й даних: DiscVault · `6180`; PostgreSQL 17 · `/data`; DiscVault · `6181`; PostgreSQL 17 · `/data`. Контрольні точки цієї сторінки: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

### DiscVault – стабільний

- DiscVault · `6180`
- PostgreSQL 17 · `/data`

### DiscVault – бета

- DiscVault · `6181`
- PostgreSQL 17 · `/data`

## Передумови

- `amd64` `aarch64`
- passkeys потребують HTTPS-адреси з доменним ім’ям перед портом застосунку; без неї використовуйте вхід за паролем із TOTP
- немає пункту на бічній панелі (Ingress): DiscVault обслуговується з кореня власного домену через зворотний проксі

## Процедура

1. **Відкрийте:** Налаштування → Застосунки → Установити застосунок → ⋮ → Репозиторії й додайте `https://github.com/helmerzNL/home-assistant-addons`
2. **Установіть:** виберіть DiscVault або DiscVault (beta) і встановіть; Home Assistant збирає застосунок на пристрої, уперше це триває кілька хвилин
3. **Налаштуйте:** `rp_id` — домен, на якому відкривається DiscVault; passkeys прив’язані до нього, тож пізніша зміна робить наявні passkeys непридатними · `rp_origins` · `trusted_proxies`
4. **Налаштуйте:** `password_login` надає ім’я користувача, пароль щонайменше з 15 символів і TOTP, коли немає HTTPS-домену
5. **Налаштуйте:** OpenID Connect: заповніть `oidc_issuer`, `oidc_client_id` і `oidc_client_secret` разом або залиште всі три порожніми · `/api/next/auth/oidc/callback`
6. **Запустіть:** початкове налаштування створює першого власника з passkey або з паролем і TOTP та один раз показує коди відновлення
7. **Перевірте:** `/api/next/health` · кінцева точка MCP розташована на тому самому порту в `/mcp`; дайте асистенту особистий ключ API

### Команди й налаштування

#### Обидва канали

```yaml
rp_id: discvault.example.com
rp_origins: https://discvault.example.com
rp_name: DiscVault
password_login: false
trusted_proxies: private
block_crawlers: true
```

```bash
curl --fail http://<home-assistant>:6180/api/next/health   # beta: 6181
```

:::caution

Безпечна межа відновлення для **Встановлення: Home Assistant** вимагає цих дій до будь-якого запуску чи продовження: Home Assistant ненадовго зупиняє застосунок під час резервного копіювання, бо робоча база даних не є узгодженою копією; секрет підпису й пароль бази даних створюються під час першого запуску в `secrets.json`; ніколи не видаляйте цей файл; бета може змінити базу даних так, що стабільний застосунок її не прочитає; ніколи не вказуйте їй теки стабільної версії; резервна копія в застосунку (Адміністрування → Backup, також за розкладом) переносить бібліотеку між Docker, Unraid і Home Assistant; новий випуск з’являється як оновлення, щойно опубліковано його образ; оновлення перебудовує застосунок і виконує міграції під час запуску.
