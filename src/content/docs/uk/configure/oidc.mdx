## Процедура

1. **Створіть:** конфіденційний клієнт OIDC у постачальника ідентичності з точною URI-адресою зворотного виклику DiscVault · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **Налаштуйте:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · задайте видавця, ідентифікатор клієнта й секрет клієнта разом або залиште всі три порожніми; часткова конфігурація блокує запуск
3. **Налаштуйте:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **Виберіть:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · дозволяйте точні приватні HTTP origins лише для endpoint токена й JWKS; issuer та авторизація у браузері залишаються лише HTTPS, перевірка TLS не вимикається, а перенаправлення discovery, token і JWKS відхиляються
5. **Запустіть:** `next-api` · `--force-recreate`
6. **Перевірте:** OIDC додає необов’язковий вхід у браузері; локальні passkeys, необов’язкові паролі, коди відновлення, API-токени й MCP bearer-токени зберігають свої ролі · ідентичність є точною парою issuer і subject; електронна пошта ніколи не прив’язується автоматично, прив’язування потребує активної сесії браузера, а від’єднання — іншого придатного способу входу
7. **Перевірте:** `auth.oidc_failed` · помилки записують лише налаштоване відображуване ім’я постачальника, безпечний код `auth.oidc_failed` і режим потоку; секрети, токени, коди авторизації, state, nonce, URL endpoint та значення PKCE ніколи не потрапляють до журналу

### Команди й налаштування

#### DiscVault v26 – бета

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```

curl --fail https://discvault.example.com/api/next/auth/status
```
