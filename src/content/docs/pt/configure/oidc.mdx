## Pré-requisitos

- acesso de proprietário · segundo método de recuperação
- [Instalação: Proxy inverso e chaves de acesso](/pt/install/reverse-proxy-passkeys/) · fora da exceção localhost, as passkeys requerem um nome de domínio completo e estável por HTTPS fidedigno; um endereço IP isolado ou HTTP simples não são suportados
- um cliente OIDC confidencial no fornecedor de identidade com o URI de retorno exato do DiscVault

### Canal privado do fornecedor

:::note[Disponível em beta]
permita origens HTTP privadas exatas apenas para endpoints de token e JWKS; o emissor e a autorização no navegador continuam apenas em HTTPS, a verificação TLS permanece ativa e os redirecionamentos de discovery, token e JWKS são recusados
:::

## Procedimento

1. **Criar:** um cliente OIDC confidencial no fornecedor de identidade com o URI de retorno exato do DiscVault · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **Configurar:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · defina em conjunto o emissor, o ID de cliente e o segredo de cliente, ou deixe os três vazios; uma configuração parcial impede o arranque
3. **Configurar:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **Escolher:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · permita origens HTTP privadas exatas apenas para endpoints de token e JWKS; o emissor e a autorização no navegador continuam apenas em HTTPS, a verificação TLS permanece ativa e os redirecionamentos de discovery, token e JWKS são recusados
5. **Iniciar:** `next-api` · `--force-recreate`
6. **Testar:** OIDC adiciona um método opcional de início de sessão no navegador; passkeys locais, palavras-passe opcionais, códigos de recuperação, tokens de API e tokens bearer MCP mantêm as suas funções · uma identidade é o par exato issuer e subject; o e-mail nunca associa automaticamente, a associação requer a sessão autenticada do navegador e a remoção requer outro método de início de sessão utilizável
7. **Inspecionar:** `auth.oidc_failed` · as falhas registam apenas o nome de apresentação configurado do fornecedor, um código seguro `auth.oidc_failed` e o modo do fluxo; segredos, tokens, códigos de autorização, state, nonce, URLs de endpoints e valores PKCE nunca são registados

### Comandos e definições

#### DiscVault v26 beta

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```text
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=http://pocket-id.pocket-id.svc.cluster.local:1411
```

```bash
cd /opt/discvault-next
docker compose -p discvault_next_deploy config --quiet
docker compose -p discvault_next_deploy up -d --force-recreate next-api
curl --fail https://discvault.example.com/api/next/auth/status
```
