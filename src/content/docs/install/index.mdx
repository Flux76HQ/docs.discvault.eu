## Goal and result

Choose the DiscVault topology for new installs, or keep an existing previous-generation deployment on the frozen Legacy image until migration.

## Applies to

`ghcr.io/helmerznl/discvault:latest` is DiscVault stable and `ghcr.io/helmerznl/discvault:beta` is DiscVault beta. The official `app/deploy/next/docker-compose.yml` and `.env.example` procedure is beta-only and uses `DISCVAULT_NEXT_IMAGE`; the advanced Docker-run procedure remains available for both channels. The frozen `ghcr.io/helmerznl/discvault:legacy` image is only for an existing previous-generation installation that is not ready to migrate. Never substitute that deployment image into the DiscVault beta topology.

### DiscVault stable

- DiscVault stable · `ghcr.io/helmerznl/discvault:latest`
- select the procedure whose channel metadata matches the running image
- PostgreSQL `17` + persistent `/data`

### DiscVault beta

- DiscVault beta · `ghcr.io/helmerznl/discvault:beta`
- select the procedure whose channel metadata matches the running image
- PostgreSQL `17` + persistent `/data`

## Prerequisites

- Docker Engine `24+`
- Docker Compose `v2`

## Procedure

1. **Choose:** [Install: Docker Compose](/install/docker-compose/) · official DiscVault beta deployment files
2. **Choose:** [Install: Docker run](/install/docker-run/) · advanced stable or beta equivalent
3. **Choose:** [Install: Unraid](/install/unraid/) · Unraid Community Applications · DiscVault launcher
4. **Choose:** [Install: Home Assistant](/install/home-assistant/) · Home Assistant app · PostgreSQL 17 built in
5. **Choose:** new installations use DiscVault `:latest` or `:beta`; only an existing previous-generation installation that is not ready to migrate should use the frozen `:legacy` image
6. **Preserve:** keep the previous generation’s volumes, environment variables, ports, and data path unchanged; never substitute `:legacy` into the DiscVault PostgreSQL Compose topology
7. **Open:** [Update and migrate: DiscVault migration](/update/migration/) · existing data → DiscVault
8. **Record:** `DISCVAULT_IMAGE` · image digest · existing or legacy deployment only: matching backup set

### Task routes

- [Install: Docker Compose](/install/docker-compose/) — DiscVault beta · official `release/v26-beta` files · `DISCVAULT_NEXT_IMAGE`

- [Install: Persistent data and PostgreSQL](/install/storage-postgresql/) — DiscVault · PostgreSQL + `/data`

- [Install: Home Assistant](/install/home-assistant/) — DiscVault · Home Assistant app · PostgreSQL 17 + `/data`
- [Update and migrate: DiscVault migration](/update/migration/) — previous generation → DiscVault · guarded import

## Expected result

A new install selects one DiscVault channel, while an existing previous-generation install either stays on its unchanged Legacy topology or follows the migration procedure.

- selected release channel
- PostgreSQL + `/data` · both DiscVault channels
- keep the previous generation’s volumes, environment variables, ports, and data path unchanged; never substitute `:legacy` into the DiscVault PostgreSQL Compose topology

## Safety and rollback

:::caution
Back up an existing or legacy deployment before pulling or recreating it; a fresh install has no prior data to back up. The frozen Legacy image receives no DiscVault features, migration improvements, or future interface updates.

- Legacy branch only: after backup, change only the existing old-generation deployment image tag to `:legacy`, pull and recreate it with its topology unchanged, verify the collection, and stop; do not switch that existing deployment to the DiscVault topology on this page
- the frozen `:legacy` image receives no DiscVault features, migration improvements, or future interface updates
- existing or legacy deployment only: matching backup set
- release notes and recorded immutable image digest
:::
