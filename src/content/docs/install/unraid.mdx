## Goal and result

Install DiscVault from the Unraid Community Applications store. The template installs the DiscVault launcher, which creates and updates PostgreSQL, the API, the worker and MCP for you.

## Applies to

Helmer’s Repository offers DiscVault and DiscVault (beta) as two templates, each with its own appdata folders, port, Compose project and network, so both run side by side.

### DiscVault stable

- DiscVault · `ghcr.io/helmerznl/discvault-launcher:latest`
- `6080` · `/mnt/user/appdata/discvault` · `discvault_stack`

### DiscVault beta

- DiscVault (beta) · `ghcr.io/helmerznl/discvault-launcher:beta`
- `6081` · `/mnt/user/appdata/discvault-beta` · `discvault_beta_stack`

## Prerequisites

- Unraid `6.12+`
- Community Applications plugin installed
- passkeys need an HTTPS address with a domain name in front of the app port; without one, use password sign-in with TOTP

## Procedure

1. **Open:** Apps → search for DiscVault → Install; the beta template has (beta) in its name
2. **Configure:** keep the default appdata folders; the launcher folder holds the generated Compose file and secrets in `/config/stack.env` · `TZ`
3. **Configure:** `RP_ID` · `RP_ORIGINS` · passkeys need an HTTPS address with a domain name in front of the app port; without one, use password sign-in with TOTP · `LEGACY_AUTH_ENABLED=true`
4. **Start:** the first start takes a few minutes while the launcher pulls the images and creates the database · the launcher mounts the Docker socket and therefore controls Docker on the server; install it only if you trust the launcher image
5. **Verify:** `/api/next/health` · the onboarding creates the first owner with a passkey, or with a password and TOTP, and shows the recovery codes once
6. **Configure:** Docker tab → Check for updates; when it starts, the launcher also updates the rest of the stack · `DISCVAULT_CHANNEL=manual` · `DISCVAULT_IMAGE`

## Expected result

The launcher has pulled the images and created the stack, the web interface answers on the template port, and the health address reports a migrated database.

- the onboarding creates the first owner with a passkey, or with a password and TOTP, and shows the recovery codes once
- `/api/next/health` · HTTP `200` · `"status": "ok"`

## Safety and rollback

:::caution
Stop the app before you copy its three appdata folders. To roll back, set the release channel to manual with the previous version tag and restore the backup made before the update.

- the beta can change the database in ways the stable app cannot read; never point it at the stable folders
- the launcher mounts the Docker socket and therefore controls Docker on the server; install it only if you trust the launcher image
- the in-app backup (Admin → Backup, also on a schedule) moves a library between Docker, Unraid and Home Assistant
- the launcher does not pass the OpenID Connect variables on yet, so the Unraid template signs in with passkeys or a password
:::
