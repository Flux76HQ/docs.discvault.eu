## 目的と結果

DiscVault を Home Assistant アプリとして実行します。アプリ、ワーカー、MCP エンドポイント、PostgreSQL 17 は 1 つのコンテナーで動き、保存内容はすべて Home Assistant がバックアップに含めるアプリのデータフォルダーにあります。.

このページ専用の手順を実行します: **インストール: Home Assistant**. この手順で扱う項目: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

## 対象

リポジトリーはポート 6180 の DiscVault とポート 6181 の DiscVault (beta) を提供し、それぞれ専用のデータフォルダーを持つため amd64 と aarch64 で並行して動作します.

このページの対象は **インストール: Home Assistant** (Home Assistant). チャンネルとデータの境界: DiscVault · `6180`; PostgreSQL 17 · `/data`; DiscVault · `6181`; PostgreSQL 17 · `/data`. このページ固有の確認点: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

### DiscVault 安定版

- DiscVault · `6180`
- PostgreSQL 17 · `/data`

### DiscVault ベータ版

- DiscVault · `6181`
- PostgreSQL 17 · `/data`

## 前提条件

- `amd64` `aarch64`
- パスキーにはアプリのポートの前にドメイン名付きの HTTPS アドレスが必要です。ない場合は TOTP 付きのパスワードログインを使います
- サイドバー（Ingress）の項目はありません。DiscVault はリバースプロキシー経由で専用ドメインのルートから配信されます

## 手順

1. **開く:** 設定 → アプリ → アプリをインストール → ⋮ → リポジトリー で `https://github.com/helmerzNL/home-assistant-addons` を追加
2. **インストール:** DiscVault または DiscVault (beta) を選んでインストールします。Home Assistant が端末上でアプリをビルドするため、初回は数分かかります
3. **設定:** `rp_id` は DiscVault を開くドメインです。パスキーはこれに結び付くため、後で変更すると既存のパスキーは使えなくなります · `rp_origins` · `trusted_proxies`
4. **設定:** `password_login` は HTTPS ドメインがないときに、ユーザー名、15 文字以上のパスワード、TOTP を提供します
5. **設定:** OpenID Connect: `oidc_issuer`、`oidc_client_id`、`oidc_client_secret` はまとめて入力するか、3 つとも空にします · `/api/next/auth/oidc/callback`
6. **開始:** オンボーディングでパスキー、またはパスワードと TOTP で最初のオーナーを作成し、復旧コードを一度だけ表示します
7. **検証:** `/api/next/health` · MCP エンドポイントは同じポートの `/mcp` にあります。アシスタントには個人用 API キーを渡します

### コマンドと設定

#### 両方のチャンネル

```yaml
rp_id: discvault.example.com
rp_origins: https://discvault.example.com
rp_name: DiscVault
password_login: false
trusted_proxies: private
block_crawlers: true
```

```bash
curl --fail http://<home-assistant>:6180/api/next/health   # beta: 6181
```

## 安全性とロールバック

:::caution
更新の前に毎回 Home Assistant にアプリをバックアップさせます。戻すときは 設定 → システム → バックアップ で復元します。データベースを変更したリリースは古いバージョンで動かない場合があります。.

安全な復旧境界: **インストール: Home Assistant** 起動または続行の前に、次の操作が必要です: 実行中のデータベースは一貫したコピーにならないため、Home Assistant はバックアップ中にアプリを少しの間停止します; 署名シークレットとデータベースのパスワードは初回起動時に `secrets.json` に生成されます。このファイルは削除しないでください; ベータは安定版が読めない形でデータベースを変更することがあります。安定版のフォルダーを指定しないでください; アプリ内バックアップ（管理 → Backup、スケジュール実行も可）でライブラリを Docker、Unraid、Home Assistant 間で移行できます; 新しいリリースはイメージが公開されると更新として表示されます。更新でアプリが再ビルドされ、起動時に移行が実行されます. このページ固有の確認点: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

- 実行中のデータベースは一貫したコピーにならないため、Home Assistant はバックアップ中にアプリを少しの間停止します
- 署名シークレットとデータベースのパスワードは初回起動時に `secrets.json` に生成されます。このファイルは削除しないでください
- ベータは安定版が読めない形でデータベースを変更することがあります。安定版のフォルダーを指定しないでください
- アプリ内バックアップ（管理 → Backup、スケジュール実行も可）でライブラリを Docker、Unraid、Home Assistant 間で移行できます
- 新しいリリースはイメージが公開されると更新として表示されます。更新でアプリが再ビルドされ、起動時に移行が実行されます
:::
