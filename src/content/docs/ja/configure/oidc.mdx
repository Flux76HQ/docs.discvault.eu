## 前提条件

- 所有者アクセス · 2 つ目の復旧方法
- [インストール: リバースプロキシとパスキー](/ja/install/reverse-proxy-passkeys/) · localhost のセットアップ例外を除き、パスキーには信頼された HTTPS 上の安定した完全修飾ドメイン名が必要です。IP アドレスだけ、または HTTP には対応しません
- ID プロバイダー側の機密 OIDC クライアントと正確な DiscVault コールバック URI

### プロバイダーのプライベートバックチャネル

:::note[ベータで利用可能]
正確なプライベート HTTP オリジンはトークンと JWKS エンドポイントだけに許可します。issuer とブラウザー認可は HTTPS のみ、TLS 検証は有効のままで、discovery、トークン、JWKS のリダイレクトは拒否されます
:::

## 手順

1. **作成:** ID プロバイダー側の機密 OIDC クライアントと正確な DiscVault コールバック URI · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **設定:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · issuer、クライアント ID、クライアントシークレットはすべて設定するか、3 つとも空にします。一部だけの設定では起動できません
3. **設定:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **選択:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · 正確なプライベート HTTP オリジンはトークンと JWKS エンドポイントだけに許可します。issuer とブラウザー認可は HTTPS のみ、TLS 検証は有効のままで、discovery、トークン、JWKS のリダイレクトは拒否されます
5. **開始:** `next-api` · `--force-recreate`
6. **テスト:** OIDC は任意のブラウザーログイン方法を追加します。ローカルのパスキー、任意のパスワード、復旧コード、API トークン、MCP bearer トークンの役割は変わりません · ID は issuer と subject の正確な組み合わせです。メールアドレスで自動リンクされず、リンクにはログイン済みブラウザーセッション、解除には別の利用可能なログイン方法が必要です
7. **確認:** `auth.oidc_failed` · 失敗時に記録されるのは設定済みプロバイダー表示名、安全な `auth.oidc_failed` コード、フローモードだけです。シークレット、トークン、認可コード、state、nonce、エンドポイント URL、PKCE 値は記録されません

### コマンドと設定

#### DiscVault v26 ベータ版

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```text
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=http://pocket-id.pocket-id.svc.cluster.local:1411
```

```bash
cd /opt/discvault-next
docker compose -p discvault_next_deploy config --quiet
docker compose -p discvault_next_deploy up -d --force-recreate next-api
curl --fail https://discvault.example.com/api/next/auth/status
```
