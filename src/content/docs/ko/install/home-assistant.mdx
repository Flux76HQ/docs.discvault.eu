## 목표 및 결과

DiscVault를 Home Assistant 앱으로 실행합니다. 앱, 워커, MCP 엔드포인트, PostgreSQL 17이 하나의 컨테이너에서 실행되며 저장되는 모든 것은 Home Assistant 백업에 포함되는 앱 데이터 폴더에 있습니다.

이 페이지 전용 절차를 수행합니다: **설치: Home Assistant**. 이 절차에서 다루는 항목: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

## 적용 대상

저장소는 포트 6180의 DiscVault와 포트 6181의 DiscVault (beta)를 제공하며, 각자 데이터 폴더를 가져 amd64와 aarch64에서 나란히 실행됨.

이 페이지의 적용 범위: **설치: Home Assistant** (Home Assistant). 채널 및 데이터 경계: DiscVault · `6180`; PostgreSQL 17 · `/data`; DiscVault · `6181`; PostgreSQL 17 · `/data`. 이 페이지의 전용 확인 지점: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

### DiscVault 안정판

- DiscVault · `6180`
- PostgreSQL 17 · `/data`

### DiscVault 베타

- DiscVault · `6181`
- PostgreSQL 17 · `/data`

## 사전 요구 사항

- `amd64` `aarch64`
- 패스키에는 앱 포트 앞에 도메인 이름이 있는 HTTPS 주소가 필요하며, 없으면 TOTP와 함께 비밀번호 로그인을 사용함
- 사이드바(Ingress) 항목은 없으며 DiscVault는 리버스 프록시를 통해 자체 도메인의 루트에서 제공됨

## 절차

1. **열기:** 설정 → 앱 → 앱 설치 → ⋮ → 저장소에서 `https://github.com/helmerzNL/home-assistant-addons` 추가
2. **설치:** DiscVault 또는 DiscVault (beta)를 선택해 설치하며, Home Assistant가 기기에서 앱을 빌드하므로 처음에는 몇 분 걸림
3. **구성:** `rp_id`는 DiscVault를 여는 도메인이며 패스키가 여기에 묶이므로 나중에 바꾸면 기존 패스키를 쓸 수 없음 · `rp_origins` · `trusted_proxies`
4. **구성:** `password_login`은 HTTPS 도메인이 없을 때 사용자 이름, 15자 이상의 비밀번호, TOTP를 제공함
5. **구성:** OpenID Connect: `oidc_issuer`, `oidc_client_id`, `oidc_client_secret`를 함께 입력하거나 셋 다 비워 둠 · `/api/next/auth/oidc/callback`
6. **시작:** 온보딩에서 패스키 또는 비밀번호와 TOTP로 첫 소유자를 만들고 복구 코드를 한 번 표시함
7. **확인:** `/api/next/health` · MCP 엔드포인트는 같은 포트의 `/mcp`에 있으며 어시스턴트에는 개인 API 키를 제공함

### 명령 및 설정

#### 두 채널

```yaml
rp_id: discvault.example.com
rp_origins: https://discvault.example.com
rp_name: DiscVault
password_login: false
trusted_proxies: private
block_crawlers: true
```

```bash
curl --fail http://<home-assistant>:6180/api/next/health   # beta: 6181
```

## 안전 및 롤백

:::caution
업데이트 전마다 Home Assistant가 앱을 백업하게 합니다. 되돌리려면 설정 → 시스템 → 백업에서 복원하며, 데이터베이스를 바꾼 릴리스는 이전 버전에서 실행되지 않을 수 있습니다.

안전한 복구 경계: **설치: Home Assistant** 시작하거나 계속하기 전에 다음 작업이 필요합니다: 실행 중인 데이터베이스는 일관된 사본이 아니므로 Home Assistant가 백업 중 잠시 앱을 중지함; 서명 비밀과 데이터베이스 비밀번호는 첫 시작 시 `secrets.json`에 생성되므로 이 파일을 절대 삭제하지 않음; 베타는 안정판이 읽을 수 없게 데이터베이스를 바꿀 수 있으므로 안정판 폴더를 절대 지정하지 않음; 앱 내 백업(관리 → Backup, 예약 가능)으로 라이브러리를 Docker, Unraid, Home Assistant 사이에서 옮김; 새 릴리스는 이미지가 게시되면 업데이트로 표시되며, 업데이트는 앱을 다시 빌드하고 시작할 때 마이그레이션을 실행함. 이 페이지의 전용 확인 지점: `6180` · `/api/next/health` · `rp_id` · `password_login` · `secrets.json`.

- 실행 중인 데이터베이스는 일관된 사본이 아니므로 Home Assistant가 백업 중 잠시 앱을 중지함
- 서명 비밀과 데이터베이스 비밀번호는 첫 시작 시 `secrets.json`에 생성되므로 이 파일을 절대 삭제하지 않음
- 베타는 안정판이 읽을 수 없게 데이터베이스를 바꿀 수 있으므로 안정판 폴더를 절대 지정하지 않음
- 앱 내 백업(관리 → Backup, 예약 가능)으로 라이브러리를 Docker, Unraid, Home Assistant 사이에서 옮김
- 새 릴리스는 이미지가 게시되면 업데이트로 표시되며, 업데이트는 앱을 다시 빌드하고 시작할 때 마이그레이션을 실행함
:::
