## Prerequisiti

- accesso proprietario · secondo metodo di recupero
- [Installazione: Proxy inverso e chiavi di accesso](/it/install/reverse-proxy-passkeys/) · al di fuori dell’eccezione localhost, le passkey richiedono un nome di dominio completo stabile su HTTPS attendibile; un indirizzo IP semplice o HTTP non è supportato
- un client OIDC riservato presso il provider di identità con l’URI di callback DiscVault esatto

### Canale privato del provider

consenti origini HTTP private esatte solo per endpoint token e JWKS; issuer e autorizzazione del browser restano esclusivamente HTTPS, la verifica TLS rimane attiva e i reindirizzamenti discovery, token e JWKS vengono rifiutati
:::

## Procedura

1. **Crea:** un client OIDC riservato presso il provider di identità con l’URI di callback DiscVault esatto · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **Configura:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · imposta insieme issuer, ID client e segreto client oppure lascia vuoti tutti e tre; una configurazione parziale impedisce l’avvio
3. **Configura:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **Scegli:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · consenti origini HTTP private esatte solo per endpoint token e JWKS; issuer e autorizzazione del browser restano esclusivamente HTTPS, la verifica TLS rimane attiva e i reindirizzamenti discovery, token e JWKS vengono rifiutati
5. **Avvia:** `next-api` · `--force-recreate`
6. **Prova:** OIDC aggiunge un accesso facoltativo dal browser; passkey locali, password facoltative, codici di recupero, token API e token bearer MCP mantengono i propri ruoli · un’identità è la coppia esatta issuer e subject; l’e-mail non collega mai automaticamente, il collegamento richiede la sessione browser autenticata e la rimozione richiede un altro metodo di accesso utilizzabile
7. **Controlla:** `auth.oidc_failed` · gli errori registrano solo il nome visualizzato configurato del provider, un codice sicuro `auth.oidc_failed` e la modalità del flusso; segreti, token, codici di autorizzazione, state, nonce, URL degli endpoint e valori PKCE non vengono mai registrati

### Comandi e impostazioni

#### DiscVault v26 beta

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```text
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=http://pocket-id.pocket-id.svc.cluster.local:1411
```

```bash
cd /opt/discvault-next
docker compose -p discvault_next_deploy config --quiet
docker compose -p discvault_next_deploy up -d --force-recreate next-api
curl --fail https://discvault.example.com/api/next/auth/status
```
