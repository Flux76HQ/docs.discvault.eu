## Procedura

1. **Utwórz:** poufny klient OIDC u dostawcy tożsamości z dokładnym identyfikatorem URI wywołania zwrotnego DiscVault · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **Skonfiguruj:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · ustaw razem wystawcę, identyfikator klienta i sekret klienta albo pozostaw wszystkie trzy puste; częściowa konfiguracja uniemożliwia uruchomienie
3. **Skonfiguruj:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **Wybierz:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · zezwalaj na dokładne prywatne źródła HTTP tylko dla endpointów tokenów i JWKS; wystawca i autoryzacja w przeglądarce pozostają wyłącznie HTTPS, weryfikacja TLS pozostaje aktywna, a przekierowania discovery, tokenów i JWKS są odrzucane
5. **Uruchom:** `next-api` · `--force-recreate`
6. **Przetestuj:** OIDC dodaje opcjonalne logowanie w przeglądarce; lokalne passkeys, opcjonalne hasła, kody odzyskiwania, tokeny API i tokeny bearer MCP zachowują swoje role · tożsamość jest dokładną parą issuer i subject; e-mail nigdy nie łączy automatycznie, łączenie wymaga zalogowanej sesji przeglądarki, a odłączenie innej dostępnej metody logowania
7. **Sprawdź:** `auth.oidc_failed` · błędy zapisują tylko skonfigurowaną nazwę wyświetlaną dostawcy, bezpieczny kod `auth.oidc_failed` i tryb przepływu; sekrety, tokeny, kody autoryzacyjne, state, nonce, adresy URL endpointów i wartości PKCE nie są nigdy logowane

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com

DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
```
