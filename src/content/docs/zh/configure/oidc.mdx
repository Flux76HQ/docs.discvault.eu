## 前提条件

- 所有者权限 · 第二种恢复方式
- [安装: 反向代理和通行密钥](/zh/install/reverse-proxy-passkeys/) · 除 localhost 设置例外外，通行密钥需要通过受信任 HTTPS 使用稳定的完全限定域名；不支持裸 IP 地址或普通 HTTP
- 身份提供商中的机密 OIDC 客户端，并配置准确的 DiscVault 回调 URI

### 提供商专用后端通道

:::note[测试版可用]
仅允许令牌和 JWKS 端点使用精确的私有 HTTP 源；颁发者和浏览器授权仍仅限 HTTPS，TLS 验证保持启用，并拒绝 discovery、令牌和 JWKS 重定向
:::

## 操作步骤

1. **创建:** 身份提供商中的机密 OIDC 客户端，并配置准确的 DiscVault 回调 URI · `openid profile email` · `https://discvault.example.com/api/next/auth/oidc/callback`
2. **配置:** `DISCVAULT_OIDC_ISSUER` · `DISCVAULT_OIDC_CLIENT_ID` · `DISCVAULT_OIDC_CLIENT_SECRET` · 同时设置颁发者、客户端 ID 和客户端密钥，或将三者全部留空；部分配置会阻止启动
3. **配置:** `DISCVAULT_OIDC_PROVIDER_NAME` · `OIDC`
4. **选择:** `DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS` · `localhost` · Kubernetes DNS · `.internal` · 仅允许令牌和 JWKS 端点使用精确的私有 HTTP 源；颁发者和浏览器授权仍仅限 HTTPS，TLS 验证保持启用，并拒绝 discovery、令牌和 JWKS 重定向
5. **启动:** `next-api` · `--force-recreate`
6. **测试:** OIDC 增加可选的浏览器登录方式；本地通行密钥、可选密码、恢复代码、API 令牌和 MCP bearer 令牌保持原有职责 · 身份由准确的 issuer 与 subject 组合确定；电子邮件绝不会自动关联，关联需要已登录的浏览器会话，取消关联前必须还有其他可用登录方式
7. **检查:** `auth.oidc_failed` · 失败时仅记录已配置的提供商显示名称、安全的 `auth.oidc_failed` 代码和流程模式；绝不记录密钥、令牌、授权代码、state、nonce、端点 URL 或 PKCE 值

### 命令和设置

#### DiscVault v26 测试版

```text
RP_ORIGINS=https://discvault.example.com
DISCVAULT_OIDC_ISSUER=https://id.example.com
DISCVAULT_OIDC_CLIENT_ID=<client-id>
DISCVAULT_OIDC_CLIENT_SECRET=<client-secret>
DISCVAULT_OIDC_PROVIDER_NAME=Pocket ID
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=
```

```text
DISCVAULT_OIDC_INSECURE_BACKCHANNEL_ORIGINS=http://pocket-id.pocket-id.svc.cluster.local:1411
```

```bash
cd /opt/discvault-next
docker compose -p discvault_next_deploy config --quiet
docker compose -p discvault_next_deploy up -d --force-recreate next-api
curl --fail https://discvault.example.com/api/next/auth/status
```
